3.1 Website Design

The website is a single scrolling page in the martini-glass structure described by Segel and Heer (2010): an author-driven opening and five chapters that each make one point, followed by a reader-driven ending where people explore the data for their own role. Every chapter uses the same pattern so readers learn the layout once:

  1. Chapter label and headline that states the finding (e.g. "Older pedestrians are hurt the worst"), so the message is readable even by someone who only skims headings.
  2. Two or three sentences of explanation. Every number in them is filled in from the same CSV as the chart, so text and chart cannot disagree.
  3. A "Try this" prompt that turns the chapter's question into a task.
  4. Controls (toggle buttons) placed directly above the chart they change.
  5. A chart card with a descriptive title, the chart and a source/caveat note.

Storyboard

3.2 Visualisation Design

Chart types were chosen from the task each chart supports (Munzner, 2014) and from how accurately people read each visual encoding: position on a common scale is read most accurately, then length, with angle, area and colour saturation read less accurately (Cleveland & McGill, 1984). Most charts therefore use position or length; colour saturation is used only on the tile map, where every value is also printed.

Graphical Integrity

Following Tufte (2001), the size of each mark should match the size of the number it shows, and the data should be shown in context.

  • Zero baselines on every bar and dot chart; the dot plot keeps zero so "twice as long" can be read from the chart. Only the indexed line chart does not start at zero, because its reference is 100 (drawn as a line).
  • Fair comparisons: growth is compared 2012 → 2019, avoiding the Victorian series break before 2012 and the COVID years after 2019. Comparing 2011 → 2021 would have shown pedestrians at −15% instead of +2%, a misleading "improvement".
  • Rates, not just counts: states and age groups use hospitalisations per 100,000 people (ABS population), so large populations do not look like high risk. Rates that rely on an approximate population split are marked "≈".
  • Context visible: COVID years shaded, the 2017 NSW counting change marked, and every chart note names the source and its main caveat. A "About the data" section lists all limitations.
  • No blame: the counterparty chart says "collided with", never "hit by"; the data records the other party, not fault.
  • Text = chart: every number in the prose is computed from the same CSV the chart uses (data-fact fields in main.js).
  • Stable scales: the age chart keeps one y-scale for both road users; the tile map's colour scale is printed with Australia's rate as a reference.

Accessibility

Checked against WCAG 2.1 (W3C, 2018). Contrast ratios were calculated with the WCAG relative-luminance formula:

  • Colour-blind safe: the only two hues that carry meaning are orange and blue, a pair that stays distinct for the common red–green deficiencies (Okabe & Ito, 2008). Everything else is grey.
  • Not colour alone (1.4.1): orange and blue have almost the same lightness (1.07 : 1), so in greyscale they look alike. Every coloured series therefore also has a direct text label, and the tile map prints each value.
  • Keyboard: all controls are real <button>s with aria-pressed; state tiles are focusable (tabindex="0", role="button") and respond to Enter/Space; a skip link jumps to the content; focus is always visible.
  • Screen readers: each chart has role="img" labelled by its title; tiles have a full-sentence aria-label; the role panel and state detail are aria-live so changes are announced.
  • Motion: the ward animation and transitions are switched off under prefers-reduced-motion.
  • Type: 16 px body, 12 px minimum chart text, Inter for UI and numbers (tabular figures), Source Serif for headings.
  • Plain language: "days in hospital" rather than "length of stay", "hospitalisations" rather than "separations", with the definition in the limitations.

Scalability

  • Responsive SVG: each chart is drawn into an SVG with a viewBox sized to its container and is redrawn when the width changes (debounced), so axes and labels are re-laid out rather than scaled down.
  • Breakpoints inside charts: under 560 px the line chart hides end labels and thins year ticks; the seasonal chart uses month initials; the ward switches from 24 to 12 columns.
  • Layout: one column, max 1,040 px; the map + detail split stacks below 760 px; control chips wrap; the nav scrolls sideways instead of wrapping.
  • Checked: no horizontal page scroll at 375 px, 1280 px and in between; light and dark modes.
  • Data size: the browser only loads six small pre-aggregated CSVs (about 280 rows in total), so the page stays fast on mobile.

Graphical Elements, Colour, Labelling and Layout

  • Focus + context colour. The whole page uses one rule: orange = pedestrians, blue = cyclists, grey = every other road user. Because the rule never changes, readers learn it once in the opening and carry it through every chapter. Greying out the context is a standard way of directing attention (Knaflic, 2015).
  • Colour is not reused for other meanings. The counterparty chart uses greys, and the tile map uses a single-hue ramp of the selected group's colour (light = lower rate, dark = higher), so orange always means pedestrians.
  • Size and weight for emphasis: focus lines are 3 px vs 1.5 px for context; focus dots are larger; the 75+ bar is full colour while the other ages are lighter.
  • Shape: a bed glyph in the opening ties the unit to the message ("hospital beds"); lines for time, dots for ranking, bars for parts and ordered categories.
  • Labelling: direct labels at line ends and on bar segments instead of legends where possible; chart titles describe exactly what is shown (measure, group, years); headlines state the finding; axis numbers use thousands separators and units ("days", "×", "%").
  • Layout: narrow text column for reading, chart cards full width; controls sit directly above the chart they change; reading order is headline → explanation → task → chart → note.

Annotations and Tooltips

  • Annotations carry the story so a reader who never hovers still gets it: "+30% 2012→19" and "+2% 2012→19" written at the 2019 points; "NSW counting change (2017)"; the shaded "COVID" and "Winter" bands; "all road users 4.9 days" on the dot plot; "average month" on the seasonal chart; "Australia" on the state chart.
  • Tooltips give detail on demand (Shneiderman, 1996) and add information instead of repeating the label: the line chart's crosshair lists all five groups for that year; the dot plot shows all three measures plus shares; age bars show count, days, deaths and rate (marked ≈ when approximate); tiles show the rate, Australia's rate and the count.
  • One shared tooltip element, kept inside the window and never covering the pointer.
  • "Try this" prompts act as task annotations: they tell the reader which control to use and what to look for.

3.3 Interaction Design

Interaction follows Shneiderman's (1996) "overview first, zoom and filter, then details on demand". Each chapter opens on its main finding (overview), toggles let readers filter or change the measure, and tooltips and the linked state chart give details on demand. Interaction is kept light: every control is a single click or tap, nothing depends on hover alone, and the story makes sense without touching any control.
